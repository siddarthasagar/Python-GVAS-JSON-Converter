# Modern Patching Workflow

This guide explains how to use the flexible patching system to modify game save files. This system allows you to create and apply different types of patches—such as "food," "jerry," or "territory"—by using a generic script and a descriptive patch template.

---

## 1. Overview

The new workflow revolves around a **generic patch template** and a **generic patch script**. Instead of having a separate script for each type of patch, we now have a single script, [`bin/apply_patch.py`](bin/apply_patch.py:1), that can read any well-formed patch template and apply it.

The [`Makefile`](Makefile:1) has been updated to support this new workflow. You can now specify the `PATCH_TYPE` you want to work with, and the Makefile will handle the rest.

---

## 2. PATCH_TYPE Usage in the Makefile

- `PATCH_TYPE` selects which patch template and workflow to use.
- Supported types include: `food`, `jerry`, `territory`, and any new type you add.
- Example commands:
  ```bash
  make patch-create PATCH_TYPE=food
  make patch-validate PATCH_TYPE=jerry
  make patch-apply PATCH_TYPE=territory
  ```
- The Makefile will automatically use the correct patch template (e.g., `patches/food_patch.json`) and pass the type to the patching scripts.

---

## 3. Patch Template Formats

Patch templates are JSON files. Each patch type may have a slightly different structure, but all follow the generic format:

### Generic Patch Template Example

```json
{
  "patches": [
    {
      "type": "update_by_index",
      "path": ["root", "properties", "ResourceBaseSaveStates_0", "Array", "Struct", "value", "SavedFoodHeld_0", "Int"],
      "action": {
        "action": "set",
        "value": 8888
      },
      "enabled": true,
      "description": "Node 0"
    }
    // ... more patch operations
  ]
}
```

### Food Patch Example

Generated by [`bin/create_patch_template.py`](bin/create_patch_template.py:1) or [`scripts/create_food_template.py`](scripts/create_food_template.py:1):

```json
[
  {
    "enabled": true,
    "food_value": 8888,
    "description": "Stage3.sav Node 0 (original value: 8888)",
    "source_file": "Stage3.sav",
    "node_index": 0
  }
]
```

### Jerry/Territory Patch Example

Structure is similar, but targets different paths and values. Always ensure `"enabled": true` for operations you want applied.

## 4. Step-by-Step Usage Instructions

### Step 1: Create a Patch Template

```bash
make patch-create PATCH_TYPE=food
make patch-create PATCH_TYPE=territory
```
- Finds the latest relevant save file.
- Converts it to JSON.
- Extracts relevant data and creates a template in `patches/<PATCH_TYPE>_patch.json`.

### Step 2: Edit the Patch Template

- Open the generated patch file.
- Set `"enabled": true` for each operation you want to apply.
- Change `"value"` or relevant fields to your desired new value.

### Step 3: Validate the Patch

```bash
make patch-validate PATCH_TYPE=food
make patch-validate PATCH_TYPE=territory
```
- Applies the patch to a temporary copy of your save file.
- Output is placed in the `temp/` directory.

### Step 4: Apply the Patch

```bash
make patch-apply PATCH_TYPE=food
make patch-apply PATCH_TYPE=territory
```
- Overwrites your actual save file with the patched version.
- Backups are automatically created in `temp/`.

### Restore from Backup

```bash
make restore
```

---

## 5. Creating New Patch Types

To add a new patch type (e.g., "queen_health"):
1. Identify the correct JSON paths in your save file.
2. Create a new patch template (e.g., `patches/queen_health_patch.json`) following the generic format.
3. Use `make patch-validate PATCH_TYPE=queen_health` and `make patch-apply PATCH_TYPE=queen_health`.

No code changes are needed if you follow the template format.

---

## 6. Migration Guidance for Legacy Patch Templates

- Legacy templates may use different JSON structures or field names.
- To migrate:
  1. Open your legacy template.
  2. Convert it to the generic format shown above.
  3. Ensure each patch operation includes `"enabled": true`, a valid `"path"`, and an `"action"` block.
- If unsure, compare with examples in [`docs/patching_system_design.md`](docs/patching_system_design.md:1).

---

## 7. Compatibility and Fallback for Legacy Scripts

- The Makefile supports both the new generic workflow and legacy Python scripts.
- Legacy commands:
  - `make extract-py`, `make patch-py`, `make convert-py`
- If your patch template is not compatible with the generic workflow, you can still use legacy scripts as a fallback.
- Migration is recommended for future compatibility.

---

## 8. Additional Notes

- Always validate patches before applying to real save files.
- Backups are created automatically, but manual backups are recommended for critical saves.
- For advanced patch types, see [`docs/patching_system_design.md`](docs/patching_system_design.md:1).
